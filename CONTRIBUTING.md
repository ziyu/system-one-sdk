# Contributing

Runtime code belongs to one package under `packages/`. Core owns contracts and validation, transports own execution, provider packages own protocol and binding behavior. Add shared code only for existing callers. LLM support stays in one adapter package.

Use Node.js 24 and `npm ci --ignore-scripts`. Run `npm run check` and `npm run test:package`; changes to Workers also require `npm run test:workers`. Node.js 20, 22 and 24 are covered by CI. Real API tests are explicit and use a supplied env file. Do not commit credentials or claim provider coverage based on fixtures.

Run `npm run changeset` for consumer-visible runtime, declaration or behavior changes. Explain affected packages, compatibility and validation in the PR. Documentation/CI-only changes may omit a changeset with a reason. Dependency ranges must include the APIs actually used; changes to shared contracts must assess dependents.

Fixes use patch, compatible features use minor. Before 1.0, breaking changes use minor and must say BREAKING with a migration guide; they never use patch. After 1.0, breaking changes use major. Exported helper subpaths follow the same policy as the main API. No runtime implementation may reach into another package's source by relative import.

Versions and package changelogs are generated by the Changesets Release PR. Do not manually bump versions or publish from a workstation. The release workflow tests immutable tarballs and publishes the checked batch. See [release operations](docs/releasing.md) and [migration](docs/migration-0.6.md).
